Pourquoi ce projet ?

Contexte & Problématique

  • 🏦Le secteur bancaire marocain fait face à un risque croissant de défaillance d'entreprises.
  • 📉Les méthodes traditionnelles (scoring manuel, ratios simples) sont limitées et subjectives.
  • ⚙️Besoin d'un outil automatisé, fiable et rapide pour classifier le niveau de risque.

❓ Question centrale

Comment prédire la probabilité de faillite d'une entreprise à partir de ses ratios financiers ?

Le jeu de données

Données utilisées

  • 🗂️Source : « Company Bankruptcy Prediction » (Taiwan Economic Journal).
  • 📊96 colonnes de ratios financiers : ROA, ROE, liquidité, endettement, activité, trésorerie…
  • 🎯Cible : Bankrupt? — 0 = sain, 1 = défaillant.
  • 🔢Environ 6 800 observations initiales.

⚠️ Problème majeur

Déséquilibre extrême des classes : ~3 % de faillites contre 97 % d'entreprises saines.

Déséquilibre des classes

1 min 30
Prétraitement

Data Cleaning

  • 1Détection & suppression des doublons.
  • 2Valeurs manquantes : imputation par la médiane (robuste aux outliers).
  • 3Détection des outliers via IQR — capping aux percentiles 1 % et 99 %.
  • 4Suppression des features à variance quasi-nulle (>95 % de valeurs identiques).
  • 5Corrélation : suppression des features avec corrélation > 0.95 (multicolinéarité).
  • 6Normalisation des noms de colonnes.

Réduction des features

96 features brutes → ~65 features pertinentes

Pipeline de nettoyage

Doublons → Imputation → IQR capping → Variance → Corrélation → Normalisation

Le piège du déséquilibre

Pourquoi générer des données synthétiques ?

  • 🤖Avec ~3 % de cas positifs, le modèle apprend à toujours prédire « sain ».
  • 🎭Accuracy trompeuse : 97 % en prédisant toujours 0 → inutile !
  • 📵Le recall sur la classe « faillite » est quasi nul sans rééquilibrage.
  • ✅Solution : augmenter la classe minoritaire avec des données synthétiques réalistes.

Génération de données synthétiques

SMOTE + Bruit Gaussien

① SMOTE — Synthetic Minority Over-sampling

Crée de nouveaux exemples en interpolant entre voisins proches (k-NN). Pour chaque exemple minoritaire, on génère un point sur le segment vers un voisin.

xnew = xi + λ · (xvoisin − xi)  λ ∈ [0,1]

② Ajout de bruit gaussien

Un léger bruit normal est ajouté à chaque feature pour éviter des données trop « lisses » et introduire une variabilité réaliste, limitant le sur-apprentissage.

xfinal = xsmote + ε  ε ~ N(0, σ²), σ = 0.01 · écart-type
